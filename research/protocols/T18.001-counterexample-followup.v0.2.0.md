# T18.001 follow-up: generalisation, diversity and feedback (exploratory)

Refs #19, #1, #12, #15; extends PR #26. Freeze this local protocol before executing the follow-up. No clinical data, rules, advice or deployment. Existing v0.1.0 findings remain unchanged. New families were authored after seeing the earlier result; this is a new exploratory holdout, not an independently adjudicated or preregistered confirmatory study.

- Reuse the original 100-case finite domain, three original development families (and, or, conditional), original mutation operators and all nine threshold pairs for training only. Exclude the original calibration and four original test families from all training, tuning and new testing. Six new test rule families: agreement_guard, exact_two, priority, fallback, majority_guard, parity_four. Nine new structural transformations (swaps, coupled transformations and conditional output modifications), disjoint by operator name and definition from original atomic mutations. Deduplicate semantic kill signatures within rule instances. Different transformations can still produce similar semantic changes. This is synthetic mutation testing, not actual CQL.
- Freeze one fixed eight-case budget per rule; nested prefixes at 1, 2, 4 and 8. Same full candidate pool and access to original rule. Compare 20 uniform random and 20 flag-stratified random sequences, old stratified boundary, original linear selector (fitted only on original development), deterministic pairwise logical/threshold-regime coverage, feedback-aware deterministic coverage (fixed adaptation: prefer new pair coverage; after a successful step break ties by original boundary proximity, otherwise by regime distance), learned marginal-gain selector without feedback, learned marginal-gain selector with feedback. Feedback arms observe only previous chosen tests and counts of newly and cumulatively exposed distinct defects, never unselected mutant outputs or hidden total. Training random histories use the same original development rule cases and atomic mutations; two ridge fits use identical training rows with and without count features; fixed ridge penalty 1, six histories per instance, seed 2401, eight sampled candidate labels per step, target new signatures / 16. No test tuning. Each arm may precompute original-rule features across 100 candidates; report that this is matching candidate/test budgets, not equal CPU or training budgets.
- Use an independently written truth-table specification and Boolean implementation for each new rule and mutation; compare exhaustively. For each held-out rule instance, exact maximum unique defect coverage via DP over attainable kill-signature bitsets at each budget is an omniscient, non-deployable ceiling only. The ceiling can see all mutant outcomes and is not a fair baseline. The oracle is separately expressed, not independently human-validated. Random replicate averages within instance; macro mean across 54 instances, equal family weight. Report family heterogeneity and nested budget curves; no population p-values (only six authored families). Primary contrast at eight tests: learned feedback vs deterministic pairwise coverage and learned without feedback; retain negative results and report if feedback does not help.
- Record seed, source/test blobs, canonical raw result SHA-256, timing and reproducibility. Use standard-library CPU implementation only. All results exploratory; upstream T00.002/003/T11.001 acceptance and T18.002 rights/runtime qualification remain separate. Do not mark a Conductor task accepted from this pilot.
